== Installation

Requires Node.js 22 or later, npm, a desktop/browser with microphone access, and configured voice services. Docker access is optional for update monitoring; do not grant Docker access to an untrusted account.

[source,bash]
----
npm ci
cp .env.example .env
# Configure the endpoints and voice mode in .env.
npm test
npm start
# Alternative, loopback browser:
npm run web
----

The browser defaults to `http://127.0.0.1:8095`. Keep its server running, or use the documented user-service launcher. In local mode, click the microphone to enable continuous conversation; after detected speech, 900 ms of silence submits automatically. After a reply, listening resumes automatically. The mic button or a spoken microphone-off request ends the loop. Clicking the avatar while recording submits early; clicking it during processing/playback cancels. Audio is capped at 30 seconds and 5 MB. To change a voice control, address her by name: for example, “Nodie, mute yourself” or “Nodie, stop listening”. She interprets natural wording such as “Hey Nodie” or “Could you mute yourself, Nodie?” and likely transcription mistakes in her name. If the intended addressee or action is unclear, she should ask for clarification. Ordinary questions do not require the name; this does not wake a muted microphone.

=== Ubuntu sandbox

On Ubuntu systems restricting unprivileged user namespaces, Electron may need an application-specific AppArmor profile. Review and run `bash scripts/setup-linux-sandbox.sh`; administrator authentication is required. The script permits user namespaces for this Electron executable only. It does not disable Chromium's sandbox or change the global kernel policy. Re-run after moving the checkout. The web interface is available without this change.

=== Configuration

`VOICE_MODE=local` selects the lightweight path. Set `LOCAL_STT_URL`, `LOCAL_STT_MODEL`, `LOCAL_TTS_URL`, `OLLAMA_URL` and `LOCAL_LLM_MODEL`. The selected local model is `qwen3.5:9b` (download with `ollama pull qwen3.5:9b`); set `LOCAL_LLM_MODEL=qwen3.5:9b`. Its voice requests disable thinking. Camera input remains a separate, unimplemented capability. The speech service must implement `/api/tts` returning WAV; the transcription service must implement `/v1/audio/transcriptions`.

Realtime mode requires `UNMUTE_BACKEND_URL`, `LLM_MODEL` and `VOICE_MODEL`. Keep dedicated speech models stopped when unused on constrained hosts. Nod.ie does not automatically start them.

=== Documentation build

Install the Ruby gems listed in `docs/Gemfile`, then run `npm run docs`. The build produces only `docs/TECHNICAL_SOLUTION_DOCUMENT.pdf`; do not commit it. Source sections and the branded theme are version controlled.

=== Optional CPU voice and persistent browser

Run `bash scripts/setup-cpu-voice.sh` to install the pinned Python runtime and verify the downloaded model checksums. Run `bash scripts/start-voice-service.sh` on Linux with a user systemd session. The service binds to loopback port 8104, uses four CPU inference threads, and is limited to 1 GB of memory and four CPU cores. Configure `LOCAL_TTS_URL=http://127.0.0.1:8104`, `LOCAL_TTS_VOICE=af_heart`, and `LOCAL_TTS_SPEED=1.06`. Other supported voices are `af_bella`, `bf_emma` and `bf_isabella`.

Run `bash scripts/start-web-service.sh` for a browser server that survives closing the launching terminal. These transient user services last for the current user session; they do not install a boot service. Stop them with `systemctl --user stop nodie-web nodie-voice`. Restart the browser server after changing `.env`.

== Optional speaker recognition (home testing)

Install Python 3 with venv support and FFmpeg, then from the repository root:

[source,bash]
----
python3 -m venv .venv-recognition
.venv-recognition/bin/pip install -r recognition/requirements-speaker.txt
python3 scripts/setup-speaker-models.py
bash scripts/start-speaker-service.sh
----

The service binds only `127.0.0.1:8106`, uses two CPU threads, and verifies model checksums at startup. It does not enable the microphone. In desktop Settings, enable _Recognise speakers during conversations_, then enable the mic normally. Recognition settings apply immediately. Rename or forget profiles in the same panel. The browser uses the same local profiles; manage them through desktop Settings.

Model downloads are separate from Nod.ie's MIT source. The Reverb segmentation weights use the https://github.com/revdotcom/reverb[Rev Model Non-Production License], permitting personal testing/research/evaluation in nonproduction environments. The downloader saves its full license and attribution beside the weights. CAM++ comes from https://github.com/modelscope/3D-Speaker[3D-Speaker], with ONNX exports distributed by https://github.com/k2-fsa/sherpa-onnx/releases[sherpa-onnx]. Review model terms before deployment beyond home testing. No model binaries or personal profiles belong in Git.

=== Unmute speaker integration

Install and start the speaker service from the speaker-diarization instructions first. Enable recognition in Settings > People; it is disabled by default.

Run `python3 unmute-service/prepare-backend.py /path/to/unmute`, followed by `python3 unmute-service/prepare-speakers.py /path/to/unmute`. When stacking memory overrides, apply the speaker preparer to their generated handler so their privacy and memory changes are retained. Set `NODIE_SPEAKERS_DIR` to this branch's `unmute-service` directory and append `compose.speakers.yml` after the other backend Compose overlays. Recreate only `unmute-backend`.

Without this backend overlay, older Unmute ignores the new field; speech continues but identity hints do not reach the model. Browser-only recognition is not exposed by this change. Raw audio remains in memory and is not retained.
