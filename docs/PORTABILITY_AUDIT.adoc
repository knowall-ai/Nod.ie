= Behaviour and portability audit

Audit baseline: `cb41234`, plus the pending conversational recognition work. This is a source review, not certification of every platform, model or language. Private household memory, credentials and recordings are outside the audit. Issue #57 tracks the work.

== Architectural boundary

Household facts (people, nicknames, relationships, pets and appearance) belong in private user memory. Per-installation choices (assistant identity, locale, timezone, endpoints, models and resource budgets) belong in validated configuration. Providers report their actual capabilities. The model interprets meaning and chooses conversational wording; code validates structured requests, freshness, permissions and confirmation before taking action. Model observations remain uncertain data, never instructions.

Finite protocol actions, limits on bytes and inference concurrency, confidence thresholds, retention choices and explicit permission checks are appropriate constraints. Species, personal names, supported everyday topics and natural-language phrasing should not be protocol enums. Adding another household must not require editing source code.

== Changes in this audit

* `lib/vision-analysis.js`: replaces the cat/coat enum with bounded animal kind and appearance fields. No household-name mapping is introduced. Tests include dogs, parrots, rabbits and tortoiseshell cats, plus rejection of oversized and malformed output.
* `lib/event-journal.js` and `unmute-service/journal_context.py`: the desktop records its timezone in the journal; backend readers use it instead of assuming London. An explicit IANA timezone override remains supported. Old journals without metadata use UTC on the backend until the desktop refreshes them.
* `unmute-service/compose.override.yml`: requires the installed `LLM_MODEL` rather than forcing a workstation-specific alias; context size is configurable. Existing deployments must supply their current model when recreating the service.

== Validation limits

General animal descriptions are supported by the event schema; individual pet recognition is not proven by these tests. Existing event records remain readable. No biometric matching threshold, permission boundary or personal memory is changed by this audit. The broader refactors above remain outstanding and should be delivered as focused reviewed changes, not represented as completed by removing the cat enum.

== Independent Opus 5.5 review

Claude Code CLI completed a read-only review using the requested `claude-opus-5-5` model. It inspected active production paths and the pending recognition work, without running tests or reading private configuration, credentials or recordings. The raw review is preserved in `reviews/2026-09-24-opus-portability.md`; its baseline findings predate the fixes in this change. Findings are review evidence, not proof of live behavior. In particular, author branding and relationship examples are not themselves household identity mappings, and CPU support already exists for several services despite GPU-specific deployment components.

The recommended sequence is configuration and capability foundations, optional integrations, model capability validation, safe recognition enrollment, multilingual intent handling, then a standalone reproducible deployment. The current fixes address only the explicitly listed items above.
