== Solution design

Nod.ie is a local voice assistant with an Electron overlay and a loopback browser interface. The renderer has no Node.js access. A narrow preload bridge exposes validated application operations to the desktop. The browser server exposes voice operations only, guarded by loopback binding, Host validation and same-origin POST checks; Docker administration is not exposed over HTTP.

=== Voice modes

* `local`: opt-in continuous conversation. Click the microphone to enable listening; recording submits after sustained voice energy followed by 900 ms of quiet. Click again to submit manually; recording stops after 30 seconds at most. Ten seconds without detected speech discards the quiet recording locally and starts a fresh bounded recording while listening remains enabled. The microphone is released before transcription and stays physically closed during replies, then resumes automatically while enabled. The microphone button or a spoken microphone-off action ends the loop. Existing Whisper, Ollama and TTS services process each turn. This avoids starting the dedicated Unmute STT/TTS models.
* `realtime`: the shared WebSocket connection sends Opus pages to Unmute, restores sessions with the system prompt after disconnects, and uses bounded reconnection backoff. Capture and playback implementations are shared between desktop and browser.

Local mode uses the configured small transcription model on demand, the existing Ollama model and an already-running TTS service. It does not start containers, load embedding models, or schedule background inference. Availability probes check service reachability; a real recorded turn is the acceptance test.

=== Trust boundaries

The model receives conversation context and a bounded read-only memory excerpt. It has no Docker, shell, payment or memory-write tools in local mode. Update decisions use deterministic adapters and reviewed plans. Release notes and memory content are untrusted data, never executable instructions.

Desktop windows use context isolation, sandboxing, navigation denial and sender-validated IPC. Configuration uses one public schema. Credentials remain in backend configuration and are not supplied to the renderer.

=== Legacy integration

MuseTalk 1.5 is optional in local mode. When LOCAL_LIP_SYNC_URL is configured and avatars are enabled, the synthesized WAV is rendered into a new synchronized speech video. Rendering failures visibly fall back to audio-only playback. The service and its measured resource use are described in the neural lip synchronisation section. Historical diagnostics and experimental modules are retained for reference but are not the supported entry points. The customised external Unmute checkout must be upgraded separately, preserving its MCP changes.

=== Circumference controls and desktop movement

Locally bundled Lucide SVGs provide microphone, camera and speaker controls in a compact arc around the avatar’s bottom-left quadrant. Icons retain their upstream licence and pinned provenance under `assets/icons/lucide`. Speaker mute applies to both local media playback and realtime Web Audio gain, with an interface-local browser-storage preference. Camera capture remains unavailable. Routine listening, thinking and speaking labels are hidden. Errors remain visible below the face, and controls do not display "click to" instructions.

Dragging uses native desktop-independent coordinates and the full display bounds, including the system panel. Partial off-screen placement is allowed while keeping a recoverable 100-DIP portion visible. Linux uses a dock-type overlay to avoid KWin moving and progressively resizing a normal window away from the panel. Saved positions use the same bounds. On the inspected 300% scaled desktop, the 300-DIP window occupies 900 physical pixels.

=== Conversational wording principle

Nod.ie chooses her own spoken wording. Application code supplies verified facts and structured events, controls timing and permissions, and selects the delivery channel. The language model composes the utterance within factual, length and tone constraints. Do not use fixed spoken scripts or a rotating list of prewritten announcements. If generation fails, show a factual status instead of silently substituting canned speech. Stable control labels, accessibility text and technical errors remain deterministic.

The requested future unfamiliar-person notification is spoken, but its wording must be generated from an event describing an unmatched face and the recognition uncertainty. Recognition must never establish permission to perform privileged actions. Camera capture, family enrolment and speaker identification are not implemented by the current controls change.

=== Assistant implementation context

Each local voice turn includes a brief implementation description with allowlisted configured model and voice names, avatar and MuseTalk behavior, bounded history, Reverie/Neo4j recall, and actual capability limits. Configuration is not evidence of successful playback or service health. No endpoints, credential paths or secrets are included. Ambiguous transcriptions should prompt clarification in Nod.ie’s own words, not an invented correction. Live Bitcoin and Lightning answers require a verified read-only snapshot.

=== Read-only node questions

The model can select the `get_node_status` tool for live node questions and follow-ups. One tool round per turn runs bounded five-second queries to the local `bitcoind` and `lnd` Docker containers. Fixed argument lists call Bitcoin `getnetworkinfo` and LND `getinfo`/`listchannels`; LND explicitly uses its `readonly.macaroon`, never the admin credential. The tool takes no arguments; unsupported names, arguments and extra tool rounds are rejected. No model-generated command is executed. Missing containers, CLI access or credentials produce an unavailable state. Other node deployments require an adapter.

The per-turn snapshot includes time, versions, open/active/pending counts, aggregate balances and reserves, and at most 20 anonymised channel summaries. It excludes peer keys, channel identifiers, addresses, credentials and raw errors. Inactive balances are distinguished from active totals; local/remote balances are not guaranteed routable liquidity. Queries are best-effort, not atomic, and are not background polling.

The model can deliver an explicit final answer through `respond_to_user`, avoiding a second model call for ordinary conversation. A node lookup needs one subsequent answer-generation call without tool definitions. If selection produces prose instead of a tool call, that draft is discarded and a final answer is generated separately. Only the validated reply or final answer reaches speech and conversation history. This separates Llama tool-selection commentary from spoken replies.

A local warm-pipeline sample measured approximately 0.2 s transcription, 0.4 s recall, 0.8–1.0 s model work, 1.7–2.5 s speech generation and 2.8–4.1 s MuseTalk rendering. Total latency was 6.2–8.0 s for different short replies, not a controlled before/after benchmark. Speech length affects both synthesis and neural rendering; the complete video is still generated before playback. The explicit reply path saves one model round on ordinary conversation, not the remaining audio/video generation time.

Recognised Bitcoin/Lightning requests and immediate metric follow-ups require a fresh snapshot before any answer, even if the model would otherwise skip the lookup. Other wording can still select the tool. This direct path avoids an unnecessary tool-selection round for recognised requests. Numeric node fields must be non-negative safe integers or canonical decimal strings; balances are capped at Bitcoin’s total supply and pending counts at one million. Malformed results are unavailable.

The desktop-only Lucide cog opens the existing Settings and security panel through sender-validated IPC. It is hidden in the browser, where administration remains unavailable. Audio-reactive waves fill the band between the portrait circumference and the displaced outer contour, so the animation grows directly from the portrait border rather than floating separately.

Voice diagnostics record duration-only `voice.stage` events for transcription, memory recall, each model call, node lookups, speech synthesis and neural lip sync. No transcript, reply or audio is logged. Timings also cover failed stages; the existing failure event identifies the failed turn.

A fixed 16-word synthetic speech benchmark on the Ryzen 5 7600 measured median CPU synthesis time of 1,665 ms with two inference threads and 1,157 ms with four (three warm samples each, identical voice and audio length). Local Kokoro therefore uses four bounded inference threads, disables idle thread spinning and retains its 1 GiB memory limit. This improves synthesis only; complete neural video generation still delays the first audible response.

The waveform uses an opaque orange band overlapping the portrait-border stroke. Temporal and neighbouring-bin smoothing reduce microphone-noise flicker. A single subtle halo stays on the base circumference rather than being redrawn on every moving contour and fill.

=== Spoken local device controls

The local voice model can call `set_voice_controls` to turn the microphone off and mute or unmute the speaker when it understands that the current speaker directly addresses Nod.ie by name and intends that device change. The model interprets flexible wording and plausible transcription errors in her name; no phrase grammar, name regex or fixed alias list controls this decision. Casual name mentions, quotations and recalled instructions do not grant intent. If uncertain, the model should ask for clarification in its own words. This is a conversational policy, not speaker authentication or an always-listening wake word. Ordinary questions do not require her name. Before returning any proposed control, a separate model-based intent check receives only the current utterance and proposed device states, without conversation history or recall. It must return a validated positive decision; negative decisions discard the action and generate a clarification, while malformed or unavailable checks fail closed. This reduces mistakes but is not deterministic speaker authentication. Arguments are validated at the backend and renderer; actions set an explicit state instead of toggling. Only the current, uncancelled turn can apply them, using the same persistent speaker preference as the button. The model writes its own acknowledgement. A speaker-mute command returns without generating speech or lip-sync video and applies silently. A microphone-off command disables continuous listening; click the microphone to enable it again. Commands are processed when the recording is submitted, including automatic submission after a speech pause; they are not continuously interpreted while recording.

Camera capture and vision remain unavailable. Requests to start the camera must explain that limitation; stopping it leaves the already-off camera off. The tool cannot start a microphone or camera, execute commands, or change arbitrary settings. These controls apply to local mode; the legacy Unmute mode does not receive this tool.

=== Local model comparison, 17 September 2026

Llama 3.1 8B Q4_K_M and Qwen 3.5 9B Q4_K_M were tested on the RTX 3090 with an 8,192-token context and 160-token output limit. Qwen thinking was disabled. Seven synthetic questions covered greetings, date, camera availability, node counts, a history-backed follow-up, explicit tool use and liquidity explanation. Each model had one initial pass and two warm passes; sampling used temperature zero and seed 42. Transcription, speech, memory and node data were fixtures for the model-only comparison. Both models remained GPU-resident during the comparison. This was a small application-specific check, not a general intelligence benchmark, and preceded the addition of the device-control tool.

|Completed warm requests |14/14 |14/14
|Typical ordinary-conversation model calls |1 |2
|Complete voice response, three synthetic turns |7.31–9.14 s |10.13–10.67 s

Complete voice tests used the same input recording, real recall, four-thread Kokoro and MuseTalk, but generated different replies. Those totals are therefore not a controlled measure of model speed alone. Synthesized audio was not played and no conversation history was persisted. Replies in this sample were longer than the earlier six-second sample. Following this comparison, the user selected Qwen 3.5 9B as the active model to prepare for a separate vision change. Qwen voice requests explicitly disable thinking; separate reasoning fields are never sent to speech. The existing explicit-final-reply safeguard remains in place. This selection prioritises the intended multimodal direction over the measured model-path latency; camera capture and vision are not enabled by switching models.

Request completion does not mean factual correctness: Llama's liquidity definition confused sending with receiving; Qwen added an unsupported “on hold” description to an inactive channel. Both need further quality evaluation. Qwen's current direct-answer behavior often triggers the application's second-call safeguard against speaking tool-selection commentary. Switching models alone does not remove the principal delay: complete speech and neural video generation before playback. Streaming speech/video segments would require a separate playback-pipeline change.

Automatic end-of-speech detection samples microphone energy every 50 ms while recording, requires 250 ms of sustained voice activity, then allows a 900 ms pause. This is a lightweight energy detector, not semantic sentence detection; loud background noise can delay submission and a long mid-sentence pause can submit early. Manual submission and the 30-second limit remain available. The detector stops on submission, cancellation and microphone release, with no microphone polling while idle.

Ollama chat requests retain the active model for 30 minutes after use. The previous default idle expiry unloaded Qwen between conversations; a measured first load added about 13 seconds before answer generation. The finite keep-alive avoids repeated loads during a session while allowing GPU memory to be reclaimed after longer inactivity. It does not perform inference while idle or remove cold-start delay after expiry.

Continuous listening is opt-in for each application session and is not restored automatically after a restart. The microphone button reflects the enabled loop, with a tooltip explaining temporary capture pauses during replies. Cancelled generations cannot reopen capture. Empty transcriptions retry at most twice before disabling the loop with a clear error; other service failures stop the loop. Expected desktop voice errors cross IPC as safe structured failures rather than Electron transport exception text.

== Optional local speaker recognition

Home-testing diarisation runs on CPU in a separate loopback service, using sherpa-onnx, Reverb segmentation and CAM++ embeddings. It starts alongside transcription and has a 1.8-second HTTP deadline. Failure leaves ordinary conversation available. Recognition is off by default; the desktop settings toggle applies immediately and is shared with the local browser backend.

Diarisation distinguishes speaker intervals; speaker matching compares those voices with local profiles. At least 1.5 seconds of non-overlapping speech is required. Cosine similarity must exceed 0.8 with a 0.1 margin over the next candidate. Scores from 0.65 to 0.8 remain uncertain rather than creating another profile. These conservative experimental thresholds need household testing and are not calibrated probabilities. Profiles are not authentication and never authorize node actions.

There are at most 32 profiles. Unnamed profiles expire after seven days without a match. Named profiles persist until forgotten. Embeddings and names live in a private, atomically replaced file under `~/.config/nodie/recognition/`; recordings are never retained by recognition. Clearing conversation history does not erase recognition profiles; Settings has separate rename, forget and forget-all controls. Forget-all also disables recognition and invalidates pending results. No recognition data is written to Reverie.

Nod.ie receives only speaker labels and time intervals, never embeddings. Multi-speaker transcripts remain unattributed because the transcription text is not word-aligned with diarisation. A sole unfamiliar speaker may introduce themselves conversationally; the model can name only that currently observed anonymous profile. Names are untrusted data. Nod.ie may ask who is speaking in her own words, no more than once per profile every five minutes. Short, ambiguous and overlapping audio can remain unidentified. Voice identities are not automatically linked to faces.

=== Unmute speaker observations

The desktop optionally records four-second, standalone WebM samples from the existing microphone stream. Recognition runs independently of the Opus speech transport, with one request in flight and no backlog. Microphone stop cancels pending results; disabling recognition invalidates the profile epoch. Names, ambiguity and an attribution hint cross the session boundary; embeddings and persistent IDs do not.

The backend accepts a typed `speaker_observation` field. It expires after eight seconds and is inserted as untrusted user-level reference data into a copy of the model messages, never into system instructions or durable conversation history. An audio window may span multiple turns; identification is advisory and is not authentication or authorization. Speaker capture does not open another microphone or wait before sending speech.
