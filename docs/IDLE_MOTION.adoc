== Idle portrait motion

The bundled six-second silent idle clip provides occasional blinks and gentle, visible head turns and tilts. The pose envelope is capped at 4 degrees of yaw, 1.8 degrees of roll and 1.2 degrees of pitch; actual movement varies smoothly below those bounds. The feathered animation region includes the hair so it follows the head. It is rendered offline with https://github.com/KlingAIResearch/LivePortrait[LivePortrait] and played locally; no extra neural model remains resident during conversation. The generated motion is applied as a difference from the rendered neutral pose, preserving the original portrait and background. First and last frames return to the same neutral pose. Keyframes are interpolated to 25 frames per second.

image::idle-avatar.png[Idle avatar,250,250]

Idle playback varies between blinking and short left/right glances, separated by quiet pauses of 1.8–4.2 seconds. Blinks are selected more often than head turns, and the same directional gesture is not repeated consecutively. A separate 2.2-degree head tilt is eligible at most once per minute and is selected less often than blinking. Each clip starts and ends at neutral. Hair follows the head pose; it is not a separate hair simulation.

=== Controls and handoff

*Idle motion* in Settings disables the clip independently of speech lip sync. Operating-system reduced-motion preferences also disable idle playback. Hidden avatars pause idle video. Missing or failed media leave the static portrait visible.

When speech audio arrives, an in-progress blink can finish (at most 360 ms), then the idle layer dissolves to neutral over 160 ms. Each response has a 750 ms initial speech buffer; subsequent audio remains independently scheduled and never waits for neural rendering. A decoded speech frame must be presented before its layer is revealed. During segment changes, a canvas holds the previous frame until the next is presented, then switches immediately instead of crossfading mouth shapes. Speech video checks its offset from the independent audio clock every 40 ms and adjusts video playback speed between 0.9 and 1.3 times normal to correct decoder startup lag; audio speed is unchanged. Cancellation clears this synchronization timer. Interruption immediately cancels audio and invalidates pending transitions. These measures avoid blank frames; perceptual smoothness still requires visual testing on the target desktop.

=== Rebuilding the bundled clip

The offline script is `scripts/render-idle-avatar.py`. It requires the official LivePortrait source at commit `9b294b3d0536135442ea73cb01e6cb3ca7029dd3` and human base/retargeting weights from `KlingTeam/LivePortrait` at revision `82a4fa6735ca58432b6ce39301b4b9ee066dea47`. LivePortrait code is MIT licensed. This path uses the calibrated bundled portrait crop, not InsightFace models or face recognition. Keep the external source and weights outside the application repository.

Use the existing `nodie/musetalk-neural:local` image with no network or GPU access, two CPU cores, an 8 GiB memory limit, a read-only filesystem and a small temporary filesystem. Mount the external source at `/liveportrait` read-only, the avatar directory at `/avatars` read-only and a writable output directory at `/output`. Run the renderer with the current user UID/GID. The default renderer writes 150 PNG frames plus short `look-left` and `look-right` frame sequences. `--tilt` renders a separate 75-frame head-tilt sequence. Keep the previously generated gentle blink clip as `nodie-idle-blink.mp4`. Encode directional clips as `nodie-look-left.mp4` and `nodie-look-right.mp4`, and the tilt as `nodie-head-tilt.mp4`. Encode each sequence with FFmpeg at 25 fps using H.264, `yuv420p`, CRF 18 and `+faststart`, without audio. Write the default sequence to `assets/avatars/nodie-idle.mp4`, look-left to `assets/avatars/nodie-look-left.mp4`, look-right to `assets/avatars/nodie-look-right.mp4`, and head-tilt to `assets/avatars/nodie-head-tilt.mp4`. Keep each output separate.

The script generates only the bundled avatar. It is not exposed through IPC or HTTP. Generated model weights and intermediate frames must not be committed. The runtime uses only the small MP4 asset, with no network download.
