== Testing

`npm test` uses Node's built-in runner and portable fixtures under `tests/unit`. It covers public configuration filtering, server path traversal and symlink escape, cross-origin voice requests, asynchronous microphone shutdown, WebSocket reconnection and prompt restoration, and update-plan mutation/expiry/digest checks. It does not require Docker, live wallets or a microphone.

Browser acceptance uses Playwright with synthetic audio and checks the complete turn without accessing the user's microphone. Live acceptance verifies transcription, an Ollama reply, WAV output and read-only memory availability. Automated tests do not prove that a user's speaker or microphone is selected correctly.

Dependency checks use `npm audit`. Updates to the pinned runtime and test tools require a fresh audit and regression run. Historical live diagnostic scripts are not the CI test suite.

Neural playback checks cover bounded MP4 responses, invalid media, unavailable-service audio recovery, cancellation during rendering and disabled-avatar behaviour. A real MuseTalk-generated H.264/AAC reply is exercised in Chromium and sandboxed Electron, including return to the resting portrait and release of media URLs. Direct dragging is checked against the native desktop-coordinate result to distinguish movement from a voice-control click. Live GPU measurements are recorded in the lip synchronisation section; CI does not require an NVIDIA GPU.

Control acceptance uses synthetic microphone input and a real generated video to check recording/send, immediate speaker mute/unmute, mute persistence, icon loading and camera remaining off. Drag boundary regressions use the measured 1280-by-674-DIP usable desktop and cover downward movement and monitors left of the primary display. Real X11 input checks confirmed downward motion centrally; intermittent user-reported edge behaviour requires observation on the user's desktop after the bounds fix.

Spoken-control checks cover silent mute without TTS/MuseTalk work, rejection of microphone-on/camera/arbitrary actions, idempotent speaker state and invalid-action atomicity. Stage diagnostics are checked for successful and failed requests and exclusion of transcript/reply/error text. A hidden-browser waveform check samples the band at five-degree intervals and radii 125–137 pixels: alpha remains 255, the portrait centre stays transparent and microphone-off motion settles.

Continuous conversation checks cover resume after playback, cancellation invalidating queued microphone starts, spoken microphone-off preventing resumption, and generated-audio browser capture across successive turns. Desktop bridge checks preserve the public no-speech message without Electron exception wrappers. The independent model intent gate is tested for current-utterance isolation, rejected proposals and malformed decisions.

=== Native desktop input region

On Linux/X11 with Python 3, libX11 and libXext installed, run:

[source,bash]
----
node_modules/.bin/electron tests/desktop-input-region.cjs
----

This creates an invisible isolated Electron window, waits for its first paint, and queries its native XShape regions. It verifies corner pass-through, avatar/button input, unchanged visual bounds and recovery when the helper stops. It does not move the pointer, click, open a microphone or access the camera. The development machine's native 900-pixel window at 300% scale passed this check; the running overlay's native region was also inspected. Unit tests additionally cover viewport mapping, geometry validation and drag retention for the polling fallback.
