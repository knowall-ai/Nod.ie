== Fixes included with integration

* Missing lip-sync configuration no longer enables the segmented audio buffer and repeated render errors.
* Speaker status/load operations avoid rewriting unchanged profiles; background matching persists last-seen at most once per minute per profile and does not consume conversational naming prompts. A regression exercises repeated matches with zero unchanged-profile writes.
* Independent local speaker recognition and memory recall run concurrently after successful transcription.
* Audio already decoded in one batch is available as future phoneme context before rendering starts. Playback does not wait for undecoded future speech.
* The worklet distinguishes silent end padding from audible underruns when adapting its buffer.
* Warm-up uses cancellable asynchronous HTTP with a total load deadline and bounded connection cleanup.
* Speaker observations refresh before backend expiry, without repeatedly publishing a disabled state.
* Scene insertion, memory save uncertainty, backend preparation order, helper recovery and recognition-setting error handling have regression coverage.

== Highest-value performance follow-ups

. *First audio latency:* the current streaming path collects up to 640 ms of audio before scheduling with a 750 ms initial buffer. Approximately 1.4 s is an inferred delay when delivery is real time, not a measured physical speech latency. Measure actual decoded-audio arrival rate and evaluate a shorter first segment while keeping later segments larger.
. *Video predecode:* reloading one video element per segment puts decoder startup on the boundary. Evaluate two alternating video elements and measure first decoded frame versus the independent audio clock. Do not hold audio to wait for late video.
. *MuseTalk stage timings:* measure feature extraction, Whisper encoding, UNet/VAE, compositing and FFmpeg independently. Warm-up should exercise real video-only segment shapes. Measure first requests after idle separately from a genuinely cold model start.
. *Contention:* measure voice with camera, face and speaker recognition individually enabled. Report p50/p95 first-audio latency, render deadlines, worker restarts and GPU residency; a separately configured vision model currently remains resident for 30 minutes.
. *Desktop idle overhead:* profile waveform redraw and transparent-window compositing when muted, listening and speaking. The browser measurement above includes the existing waveform redraw, but not the physical desktop compositor.
. *Interruption recovery:* measure context teardown/recreation and busy-render responses before changing their cancellation semantics. Check microphone echo/ducking against actual playback time.

== Functional limitations and remaining acceptance work

* Unmute matches voice profiles learned through deliberate local-mode turns; it does not yet enrol or name new speakers conversationally. Household accuracy and overlapping speech remain uncalibrated.
* Face profiles are explicitly opt-in and managed in Settings. Their results are not yet used in voice conversation; conversational face naming and unfamiliar-person notifications remain future work. No image or voice match authenticates a person.
* A camera snapshot disables memory tool execution for the remainder of that backend connection. The UI and prompt now explain this limitation. A fresh connection restores availability when no snapshot is supplied again. Camera descriptions remain untrusted reference data.
* Local transcripts persist, but previous Unmute sessions are not automatically inserted into current model context.
* Unmute prompt time is captured when the connection configuration is prepared; refreshing it for long-lived sessions remains follow-up work.
* Settings currently reconnect voice even for visual-only changes. Applying those changes without losing backend conversation state remains follow-up work.
* Face inference starts a separate Python process per selected frame. A persistent bounded worker should be evaluated if measurements show startup is material.
* Physical microphone/speaker latency, live duplex interruption, camera-then-memory wording, backend restart recovery and extended desktop playback still require runtime acceptance on the final deployed build.

== Final review disposition

The individual review's frame-rounding concern was checked against the actual flush path: render WAVs are padded to whole video frames before trimming. Applying the suggested floor would unnecessarily discard a padded render frame.

Additional non-blocking follow-ups: cap permanently failing X11 helper restarts and offer pointer-tracking fallback; preserve text-presentation symbols in emoji filtering where appropriate; evaluate a persistent face worker; clean up cancelled upstream tool streams before reusing their protocol; and make visual-only settings changes avoid voice reconnection. These are not claimed as completed in this integration.

== Head-motion endpoint correction

Adjacent-frame measurements found a discontinuity in all four head-motion clips: endpoint differences of 1.46–1.61 grayscale levels versus median interior differences of 0.095–0.133 (256×256 analysis). Matching the stitched neutral reference and easing the neural residual over eight frames reduces endpoint differences below 0.02 grayscale levels. Clips remain 25 fps at 768×768; the blink-only clip is also rebuilt against the aligned reference. These measurements address encoded pose jumps, not desktop dropped frames or speech rendering throughput. The neutral reference now uses the same stitching transform as moving poses. All five clips are rebuilt from that aligned reference, with easing applied before CRF 18 encoding.

== Sustained speech recovery and direct vision

The streaming renderer now skips jobs unlikely to finish before their audio ends, decays stale timing estimates and retries after transient failures. A failed render no longer disables all video for the remainder of a reply. Gaps over 250 ms return to idle instead of holding an indefinitely frozen mouth. Audio timing remains independent.

A controlled headless Chromium comparison used fourteen 640 ms clips and synthetic render delays, without GPU inference. At 450 ms per render, displayed frame callbacks were 220 before and 218 after. At 720 ms per render, callbacks increased from 64 to 128, while p95 frame gaps fell from 383 to 300 ms; the worst gap increased from 650 to 767 ms because unrecoverably late clips are skipped. With the first render failing, the old path displayed zero frames for the whole reply; the revised path recovered and displayed 200. These are controlled playback measurements, not physical desktop frame-rate guarantees. Offscreen preloading was tested and removed because it worsened normal playback. GPU throughput remains a limit under concurrent workloads.

A real request through the voice model's OpenAI-compatible endpoint, with an attached JPEG of the bundled portrait, correctly identified the shirt color and Bitcoin logo in 1.45 seconds. This verifies multimodal delivery; it does not establish real-room object-recognition accuracy.
